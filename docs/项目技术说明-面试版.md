# 大华 AI 解决方案助手：项目技术说明与面试讲解稿

> 用于面试展示、项目复盘和后续维护。当前项目是可运行的安防售前工程原型，重点验证“需求理解—设备选型—工程计算—人工审查—交付物生成”闭环。

## 1. 项目定位

这是一个面向大华/海康类安防售前解决方案工程师的本地 Web 方案工作台。用户可以输入自然语言需求、上传招标文件或 Excel 点位表，系统完成需求结构化、场景拆解、产品选型、存储与网络测算、工程风险检查，并生成 Word、Excel、PPT、拓扑图和方案包。

核心原则：

> 大模型负责理解、改写和辅助问答；关键数字、型号白名单、容量、带宽和工程阻断由确定性代码负责。

项目不是“完全自动投标”，而是输出可审阅、可解释、可回溯的售前方案草稿。

## 2. 解决的问题

安防售前需要把客户口述、招标条款、点位表、产品目录、厂家方案和工程计算整理成一套交付材料。传统做法容易出现：

- 点位、录像天数和行业口径遗漏；
- 推荐型号没有选型依据；
- 存储、带宽、NVR 和交换机数量依赖人工经验；
- 方案没有风险、待确认项和版本记录；
- 大模型编造型号、数字或不存在的能力。

本项目用模块化流程把这些工作统一，并保留人工审阅节点。

### 4.1 LangGraph 节点

agent/graph.py 是唯一流程编排入口：

| 节点 | 作用 |
|---|---|
| intent | 需求解析、行业识别、场景和点位分配 |
| research | 调用检索、容量计算、竞品工具 |
| selection | 按场景和行业选择摄像机 |
| bom | 配齐 NVR、硬盘、交换机、平台和显示 |
| solution | 组装 Spec 并执行硬闸门校验 |
| ask_gap | 缺少硬输入时中断，等待用户补充 |
| review | Spec 生成后中断，等待通过或修改 |
| deliver | 通过后生成交付物 |
| abort | 缺口超过轮次后停止，不输出半成品 |

LangGraph 只承担三件事：SQLite checkpoint、human-in-loop 中断、校验失败条件回边。业务计算不放在 Prompt 中。

## 5. 核心数据模型

app/models.py 的 Spec 是所有流程和导出的统一中间表示：

    Spec
    ├── project          项目名称、行业、行业标签、规模
    ├── requirements     场景、建设目标、点位数、码流
    ├── devices          类别、型号、数量、价格、理由、证据
    ├── storage          录像天数、编码、裸容量、冗余容量
    ├── network          上行带宽
    ├── topology         拓扑分层
    ├── boundaries       范围、排除项、假设
    └── gaps             待确认缺口

Device 除基础采购字段外，还保留 evidence、alternatives 和 selection_engine，用于解释“为什么选它”和“还有哪些候选”。

## 6. 关键模块职责

### app/api.py

FastAPI 主入口，负责页面、Agent、点位表、招标文件、RAG、竞品、导出、会话归属和权限。

主要接口：

| 接口 | 作用 |
|---|---|
| POST /api/agent/start | 启动方案流程 |
| GET /api/agent/{thread_id}/state | 获取状态 |
| POST /api/agent/{thread_id}/resume | 缺口补充、审阅通过或修改 |
| POST /api/agent/{thread_id}/auto-fix | 安全的自动工程修正 |
| POST /api/agent/{thread_id}/edit | 修改已生成方案 |
| POST /api/pointlist/analyze | 解析 Excel 点位表 |
| POST /api/tender/analyze | 解析招标文件 |
| POST /api/requirements/review | 启动前需求完整性检查 |

### app/builder.py

方案确定性核心：

1. analyze：行业识别、场景匹配、点位分配；
2. select_cameras：按规则、能力和 RAG 结果选择摄像机；
3. plan_bom：生成 NVR、硬盘、交换机、显示、平台等 BOM；
4. assemble_spec：将 Plan 和 BOM 组装成 Spec；
5. validate_spec：检查型号白名单、数量和关键字段。

### app/calc.py

关键数字统一由公式计算：

    单路单天数据量 = 码流(Mbps) × 86400 ÷ 8 ÷ 1024
    裸容量 = Σ(路数 × 单路单天数据量) × 保存天数 ÷ 1024
    冗余容量 = 裸容量 × 冗余系数
    上行带宽 = Σ(路数 × 码流) × 并发系数

公式和参数会进入方案假设，避免模型直接生成数字。

### app/selection.py

产品选型采用多层证据：

1. 真实方案配单；
2. 中标项目明细；
3. RAG 相似场景召回；
4. 类目、形态、能力标签和反场景词过滤；
5. 可选的大模型候选复排。

大模型只能在候选列表中选择，不能编造新型号。

### app/engineering_checks.py

输出 pass、warn、block 三种等级，检查：

- 点位和存储天数是否明确；
- 摄像机数量是否与点位一致；
- NVR 通道是否足够；
- 硬盘是否超过 NVR 盘位；
- 交换机端口是否足够；
- 存储容量是否闭合；
- 网络是否仅完成粗算；
- 型号是否有产品库/方案库依据；
- 交管项目的平台接口和算法授权边界。

### app/auto_fix.py

只自动处理可以确定计算的工程问题。当前可根据硬盘数量和 NVR 盘位自动修正 NVR 数量，重新生成交付物，并记录 auto_fix_log。涉及协议、RAID、机房、平台和第三方对接时不擅自更换型号。

### app/package.py

统一生成方案书 Word、报价单 Excel、点位表 Excel、工程审查清单 Excel、拓扑 PNG、汇报 PPT 和方案 ZIP。

### app/sessions.py

维护 sessions、versions、exports 三张会话索引表。版本摘要保存设备数量、容量、价格、工程审查结论和 AI 修改记录。

### scraper/

只处理公开资料：产品目录、方案案例、中标公告、海康公开参数、产品与 BOM 对齐、清洗、去重、导入和状态检查。采集层不参与在线主流程。

## 11. 面试讲解重点

### 为什么不让大模型直接生成方案？

因为路数、码流、容量、带宽、型号和价格属于可审计工程数据。模型可以理解“地下车库”“人车通行”等口语，但不能直接决定 30 天需要多少硬盘。因此模型被限制在语义层和候选复排层，关键数字由 Python 公式和产品白名单控制。

### 为什么保留人工审阅？

真实方案还受现场勘察、供电、光纤、平台协议、授权、机房和商务价格影响。系统应该列出不确定项，而不是伪装成已经确认。人工审阅是安全边界。

### 项目的工程价值

- 统一需求输入；
- 减少点位和天数漏项；
- 保留计算和选型依据；
- 快速形成设备清单；
- 提前暴露明显工程问题；
- 让版本和修改原因可追溯。

### 当前边界

这是个人作品和工程原型，不能直接替代正式投标审核。产品彩页、NVR 盘位和带宽、PoE 功率、VLAN、光纤、平台授权、商务价格、施工和维保仍需人工确认。
